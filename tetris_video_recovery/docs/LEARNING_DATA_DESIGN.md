# 動画からテト譜を出すAIのための学習データ設計

## 結論

最初から「動画一本を入力して URL 文字列を直接出す」だけを教師にするのは避ける。
URL は圧縮済みの最終表現で、誤りの原因（ネクスト、設置、ライン消去、下穴上昇）を分けて学習・検証できないためである。

このツールが人間の確認を経て出力する
`training/<video>_<sha16>_training.v1.json` を、一本の動画に対応する**正解軌跡**として保存する。既定では、対応動画も `training/video/` にハードリンク（別ボリュームなどで不可ならコピー）で保存するため、元ファイルを移動・削除してもデータセットだけで学習できる。容量を節約したい場合だけ、出力画面のチェックを外して外部動画パス参照にする。

## 1 サンプルの構造

```text
data/exports/<video>/training/
├─ <video>_<sha16>_training.v1.json
├─ <video>_<sha16>_manifest.v1.json
└─ video/<video>_<sha16>.mp4
   ├─ source.videoPath / source.originalVideoPath / source.sha256
   ├─ dataset.selfContained / dataset.videoFile / dataset.videoStorage
   ├─ stateConvention
   ├─ queueObservations.p1[] / queueObservations.p2[]
   │  ├─ time, active, hold, next         # 各スキャン時刻の生認識
   │  ├─ stable                            # その時点で確認回数を満たしたか
   │  └─ manual                            # 人がこの行を修正したか
   └─ players.p1[] / players.p2[]
      ├─ start, time                 # 動画上の局面範囲
      ├─ active, hold, next, action  # キュー状態
      ├─ observed                    # ONNX の投票結果（補助ラベル）
      ├─ fullBoard, board            # 消去前 / 消去後の正解盤面
      ├─ placement                   # piece, x, y, rotation, clearedLines
      ├─ garbage                     # lines, holeMasks, manual
      └─ manual                      # 候補を人が固定した局面か
```

`holeMasks` は追加された下穴行を上から順に表す 10 ビット値で、1 が穴、0 が灰色ガベージである。この復元モードでは**各値に立つビットは必ず一つ**であり、観測が崩れて複数の空きに見えた場合も、人間が一つの穴列を選ぶ。これにより不可能なガベージ形を教師へ混ぜない。

`board` は状態遷移の正解、`fullBoard` はライン消去演出を含む正解、`placement` は行動ラベルである。これらを併記することで、盤面だけ／設置だけ／テト譜全体のどのモデルにも同じデータを使える。

`queueObservations` は局面へ安定化した後の値ではなく、動画を一定間隔で走査した**生の認識ログ**である。`time` の順に並び、レビュー画面の「時刻別Next認識ログ」で行単位または複数行単位に修正できる。修正後はこのログから確認回数、局面境界、active/hold/next、合法手ビームを再計算するため、局面の結果だけを直接書き換えるよりも、誤認識が起きた時刻を教師データとして残せる。

生ログから局面へ変換する際は、直前の安定キューに対するスライド整合性も使う。同一キュー、1個進んだキュー、2個進んだキューだけを通常遷移として扱い、それ以外の認識は保留扱いにする。2個進んだ場合は途中のミノが画面に現れなかったことを示すスキップ局面として保持する。このルールにより、演出フレームの無関係なNext配列を2回見ただけで教師ラベルへ採用することを防ぐ。

## 学習の段階

### A. 観測モデル（高速で最初に作る）

入力は 1P/2P の盤面・ホールド・ネクスト周辺の連続フレーム、出力は以下に分ける。

- 200 セルの状態と信頼度
- ホールドと 5 個のネクスト
- ガベージ行数と各行の穴マスク
- 設置・ホールド・ライン消去の境界時刻

現行 ONNX は A の盤面ヘッドのベースラインとして残す。人が確定した `board` を再学習ラベルにできるため、派手な演出・低画質・色違いに対して改善を測れる。

### B. 時系列復元モデル

動画全体、または局面の前後 1.5 秒程度のクリップを入力し、各局面の `placement`、`garbage`、キュー遷移を出力する Transformer / Temporal CNN を学習する。

推論時はモデルの確率をこの C++ の合法手生成・ビームサーチのスコアに加える。AI が候補を絞り、ゲームルールが不可能な遷移を除外する構成にする。完全なブラックボックスの URL 生成より、誤りを候補画面で修正でき、必要な計算量も小さい。

### C. 全動画出力

最終的には A+B を一つの動画エンコーダにまとめてもよい。ただし出力は URL ではなく、まず `training/v1` と同じ局面列にする。各局面の `simulatorNext` は操作中ミノを先頭に戻した、Simulator表示用の時系列キューである。最後に既存のシリアライザで Simulator URL を生成する。この分離により、シミュレータ形式が変わっても学習済みモデルを捨てずに済む。

## データ品質の運用

1. 動画を解析し、候補カード・動画プレビュー・下穴補正で確認する。
2. 「確認済みテト譜を出力して開く」を押したものだけを教師候補にする。
3. `manual=true` は人が候補を明示選択した強い根拠、`manual=false` は人が確認して承認した自動復元として扱う。
4. `source.sha256` が一致しない動画にはラベルを再利用しない。
5. 学習/検証/テスト分割は**局面単位ではなく動画・対戦単位**で行う。同一動画の隣接局面が別 split に入るリークを防ぐ。

最初の品質指標は、セル一致率だけでなく、ネクスト一致率、合法遷移率、設置 `(piece,x,rotation)` 一致率、下穴マスク F1、最終 Simulator 盤面一致率に分ける。

## 収集時に増やすとよい情報

- ゲーム名・ルール・解像度・配信レイアウト・画質
- 演出が被った局面、下穴補正をした局面、保留を使った局面のタグ
- 人間が「確信あり／保留」と判断した品質フラグ
- 元動画を共有できない場合の、学習用に切り出した匿名クリップ

これらは次の `training/v2` で追加できる。v1 は正解の局面列を安定して蓄積するための最小で後方互換性の高い基盤とする。
