# Tetris Video Recovery

動画からテトリスの盤面履歴を復元する、シミュレータから独立した Windows ネイティブ版です。

## 起動

`start.bat` をダブルクリックしてください。動画ファイルを選ぶと解析を開始します。解析完了後はすぐにURLを書き出さず、確認・合法手修正画面を開きます。

1. P1/P2 と局面を選びます。左の局面・タイムスタンプ行をクリックすると、動画プレビューもその表示時刻へ正確にシークします。
2. 左から「修正済みの前盤面」「ONNX投票の観測盤面」「選択した合法候補の着地盤面」を確認します。
3. 右側の候補リストから、復元器と同じ合法手生成による候補だけを選べます。ONNX観測盤面をクリックすると、そのセルに色ミノがある候補だけに絞り込めます。さらに、**前盤面をクリックして次のミノを最大4セル描く**と、その4セルを実際に置く合法手だけに絞り込めます。
4. **時刻別キュー認識ログを開く（現在ミノ / Hold / Next）** を押すと、解析時刻ごとの生ログと専用の動画枠が開きます。初期サイズは広く、最小でも1100×720なので、ログ・編集欄・動画を同時に確認できます。行を選ぶと専用動画枠がその時刻で停止します。現在ミノ・Hold・Next1〜5を修正でき、Ctrl/Shiftで複数行を選んで同じ修正を適用できます。**選択行のNEXT履歴をコピー** と **全NEXT履歴をコピー** は、認識値と復元値の両方をクリップボードへ出します。
5. **修正を反映して局面を再解析** を押すと、キュー安定化・局面の時系列・合法手候補を最初から再計算します。簡易の局面キュー修正欄はありません。元の認識へ戻す場合は、生ログ画面の **選択行を元の認識へ戻す** を使います。
6. **選択候補で固定して以降を再探索** を押すと、選んだ盤面をアンカーにして、その後の局面だけをビームサーチで再計算します。
7. 内容を確認した後、右上の常時表示される **テト譜を出力して2Pシミュレータを開く** を押すと、JSON・HTMLレポート・P1/P2/2Pの`.url`を出力し、2P用の`.url`経由で既定ブラウザを開きます。

ネクスト認識は単純な「同じ値を2回見たら確定」ではありません。全スキャンの5個NEXTを重なり合う配列として圧縮し、同一・1スライド・2スライドだけを許す全履歴ビームで一本のNEXT列を復元します。既定ではGuideline 7-bagも厳密に満たします。したがって `OJSIT` から末尾だけ `OJSIO` になった行は、局所的に確定させず `→復元=OJSIT [補正:全履歴/7-bag]` として表示され、余計な設置イベントの入力には使われません。`queueObservations` の `next` は生認識、`decodedNext` は復元値、`sequenceCorrected` は補正有無です。

開幕では、最初のミノをHoldした直後にNEXTのスライド演出が遅れて見えることがあります。局面の現在ミノは区間の終端直前の状態を採用するため、この `TをHold → Zが出現` のような遷移でもZを落とさず譜面へ記録します。

後続の手動修正がある状態で前の局面を直す場合は、盤面のつながりを保証するため、その後の手動修正を解除してから再探索します。レポートとJSONには手動で固定した局面も記録されます。

実行ファイルを直接起動する場合は `bin\TetrisVideoRecovery.exe` を使用します。

レビュー画面は起動時からモニターいっぱいに最大化されます。タイトルバーを消した完全な全画面にする場合は画面右上の **全画面 (F11)**、またはキーボードのF11を押してください。

## 構成

- `models\tetris.onnx`: 200セルを一括推論する画像認識モデル
- `third_party\onnxruntime`: ONNX Runtime の Windows x64 実行環境
- `config\tetris_recover.ini`: 動画レイアウト・サンプリング・探索設定
- `data\exports\<動画名>`: JSON、P1/P2/2P の `.url`（ダブルクリックで既定ブラウザを開く）、HTMLレポート、学習データ
- `src`, `include`: C++実装

盤面認識は色分けの代替処理ではなく、`動画解析.html` と同じ63特徴量のONNX推論を使います。ネクスト／ホールドの判定、2回連続確認、区間内の複数フレーム投票、盤面シフト判定、ビーム探索の採点値、そして元ファイルの「接地する全候補手」の生成をC++に移植しています。`TetrisEngine` にはシミュレータ準拠のSRS到達可能手生成も保持していますが、既定の復元パイプラインは元ファイルと同じ候補生成を選びます。

`config\tetris_recover.ini` の盤面矩形は、このPuyo Puyo Tetris動画の内側10×20セルに合わせて調整済みです。これにより外枠の青／赤をONNXがミノと誤認識する問題を避けます。一方でネクスト／ホールド座標は元ファイルと同じ1280基準のままです。ホールドとネクストは常に有効なミノ文字だけをURLへ出力するため、盤面のゴミブロック `G` がHold/Next欄へ混入しません。

## ビルド・テスト

LLVM/Clang が `C:\Program Files\LLVM\bin\clang++.exe` にある環境では、次を実行します。

```powershell
./build.ps1
./test.ps1
```

ONNX Runtime は[公式 v1.23.0 Windows x64 リリース](https://github.com/microsoft/onnxruntime/releases/tag/v1.23.0)を `third_party\onnxruntime` に同梱しています。配布済みの `bin` には実行に必要なDLLも配置済みです。

## 動画を見ながら修正する

解析が終わると、いきなり出力せず確認画面を開きます。動画プレビューは最初の選択局面で停止表示まで自動初期化されるため、最初に`再生`を押す必要はありません。局面・タイムスタンプ行を選ぶと右側の動画プレビューはその時刻へシークされ、`再生`、`局面の前から`、`±0.5 秒`で演出や着地を確認できます。

- 合法手は右端の**盤面カード**です。カードをクリックすると、中央に消去前の着地盤面を大きく表示します。
- 中央のONNX観測盤面をクリックすると、そのセルを含む候補だけに絞り込めます。
- 左の確定前盤面をクリックすると、次に置くミノをその色で重ね描きできます。描いたセルをすべて含む候補だけを残すため、Jなどの着地形を4セル描けば通常は一つまで絞れます。
- 下穴が演出で見えなかった場合は、動画の下にある「下穴せり上がり」の段数を変えます。黄色が穴で、各行をクリックすると**その列だけ**が穴になり、他の穴は自動で塞がれます。設定は即時に候補の合法手生成へ反映されます。
- 選択候補を固定すると、その局面をアンカーにして以後だけを再探索します。前の局面を直す場合、以後の手動修正は再計算対象になります。

出力ボタンを押したときだけ Simulator URL、通常の復元JSON、HTMLレポートに加え、学習用の確定アノテーションを `data/exports/<動画名>/training/` に保存します。既定で「学習データに動画も保存」がオンなので、同フォルダの `video/` に元動画のハードリンク（できない場合はコピー）を置く自己完結型データセットになります。容量を増やしたくないときだけ、出力前にチェックを外してください。

## 学習データ

学習用JSONには、人が確定した盤面列、消去前盤面、設置ミノの座標・回転・消去数、ネクスト／ホールド、下穴の段数と各行一つの穴、動画タイムスタンプ、元動画のSHA-256を保存します。さらに `queueObservations.p1/p2[]` に、修正前後を含む**各スキャン時刻の生のHold/Next認識**を保存します。既定では対応動画も同じ `training/video/` に保存されます。元動画を入力してテト譜全体を出すAIは、この局面列と時刻別認識列を教師にし、最後に既存のシリアライザでSimulator URLへ変換する構成にします。

詳しいデータ構造と段階的な学習方針は [docs/LEARNING_DATA_DESIGN.md](docs/LEARNING_DATA_DESIGN.md) を参照してください。
