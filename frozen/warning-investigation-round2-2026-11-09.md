# 警告4試合の原因調査（2026-11-09 ラウンド2）

対象: 警告が出る6試合（10,12,14,19,26,27）をマニフェスト指定で高速に反復。
基準（既定設定）: 警告 [12,14,26,27] / 不一致区間 30

## 設定スイープ結果（すべて同じ4試合が残る）

| 設定 | 区間数 |
|---|---|
| 既定（confirm=2, boundary=confirmed, beam96/500/256, conf0.5, tail0.85, samples5） | 30 |
| confirm=3 | 26 |
| boundary=first | **16** |
| boundary=first + beam強化 | 17 |
| boundary=first + beam強化 + confirm3 | **16** |
| 確信度しきい値 0.35 | 23 |
| 確信度しきい値 0.25 | 19 |
| beam 96→512 / 500→3000 / 256→1500 | 17 |
| 連鎖除外 tail 1.20s | 33 |
| 連鎖除外 tail 1.60s | 24 |
| 盤面サンプル数 3 | 30 |
| 盤面サンプル数 8 | 30 |

→ **区間数は最小16まで減るが、警告される試合は一切変わらない。**

## 分かったこと
1. 不一致区間は**ライン消し・連鎖（REN）の最中**に一致する
   - 例: 試合27 P1 の不一致区間（phase 36-45）は 1REN→7REN の連鎖中で、
     盤面がアニメーションしており読み取りが不安定
2. キュー（NEXT）側は自己整合している箇所が多い
   （記録された next 列と画像から読んだ値が一致）
3. 盤面モデルは全ファイル同一（DA60D1C9A329）で、差し替え先が無い
4. したがって原因は**連鎖中の盤面認識**であり、設定では解決できない

## 実装した追加機能（今後に使える）
- `TR_QUEUE_BOUNDARY=first|confirmed`: フェーズ境界の決め方
- `TR_BOARD_TAIL_SECONDS` / `TR_BOARD_TAIL_BORDERLINE_SECONDS`: 連鎖除外時間
- `TR_QUEUE_CONFIRM_DEBUG`: fpsと確定回数のログ
- ビルド: v44（`scratch/end3/build/TetrisVideoRecovery_stream_v44.exe`）
